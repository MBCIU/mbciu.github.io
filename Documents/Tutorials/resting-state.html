Resting-state fMRI

Preprocessing, confound decisions and connectivity QC

Research training guide · Updated 14 October 2026. Examples use placeholder paths and require adaptation to your acquisition and installed software. Test one participant before scaling to a cohort.

1. Prepare BIDS data

Organise BOLD and anatomical scans by participant and session. Verify repetition time, slice timing where available, phase encoding and fieldmap associations. Run a BIDS validator and resolve errors before preprocessing. Inspect the raw scans, including temporal coverage and motion.

2. Run fMRIPrep

Use a versioned container and a valid FreeSurfer licence. Run on an allocated compute node with sufficient resources. This minimal example assumes the image and paths already exist; choose additional spaces and acquisition-specific options in your study protocol.

apptainer run --cleanenv \
  --bind /path/bids:/data:ro,/path/derivatives:/out,/path/work:/work,/path/license.txt:/license.txt:ro \
  /path/fmriprep-VERSION.sif /data /out participant \
  --participant-label 001 --fs-license-file /license.txt -w /work

3. Decide on postprocessing

fMRIPrep outputs require an explicit downstream denoising plan. If using XCP-D, check compatibility with the selected fMRIPrep output format and read documentation for the pinned XCP-D release. Specify confound strategy, motion censoring, temporal filtering, atlas and minimum retained data before comparing participants.

Do not copy command flags between XCP-D releases without checking --help. Keep the same preprocessing and postprocessing decisions across visits.

4. Review reports and matrices

  • Inspect brain extraction, BOLD-to-T1 alignment, normalisation and susceptibility correction in each fMRIPrep report.
  • Review framewise displacement, DVARS, censoring and retained duration.
  • Inspect atlas coverage and parcel time series after denoising.
  • Check matrix symmetry, parcel ordering, missing parcels and unusually uniform rows.

Store the atlas name/version and parcel labels alongside every connectivity matrix. Record whether correlations have been Fisher transformed. A successful pipeline exit does not replace report review.

Record your analysis

Retain the participant/session manifest, input checksums, software versions, commands, completion status, QC reviewer and decision, and reasons for missing or excluded measurements. Keep raw inputs separate from derivatives.
