Spartan workflows

Safe, reproducible SLURM workflows for MBCIU neuroimaging

Purpose. Use this guide to move from an interactive prototype to a traceable Spartan batch workflow. Do not run compute-heavy neuroimaging commands on the login node.

1. Connect to Spartan

ssh YOUR_USERNAME@spartan.hpc.unimelb.edu.au

Use a University-approved SSH method and multifactor authentication where required. Read the message of the day because outages and module changes are announced there.

# Useful first checks
hostname
whoami
pwd
groups
sinfo --summarize

2. Organise inputs, outputs and logs

Keep immutable inputs separate from generated derivatives. Replace punimXXXX with the actual Spartan project ID.

PROJECT_ROOT=/path/to/your/punimXXXX/project
mkdir -p "$PROJECT_ROOT"/{inputs,derivatives,scripts,logs,manifests}

# Record files before processing
find "$PROJECT_ROOT/inputs" -type f -print0 | sort -z | xargs -0 sha256sum \
  > "$PROJECT_ROOT/manifests/input_sha256.txt"
Never put passwords or tokens in job scripts. Keep credentials outside the repository, restrict permissions, and remove temporary credential files when a transfer finishes.

Transfer from Mediaflux

The University provides restartable Mediaflux clients on Spartan. Discover the current module name before loading it, and keep transfer concurrency modest.

module spider unimelb-mf-clients
module load unimelb-mf-clients
unimelb-mf-check --help
unimelb-mf-download --help

3. Use reproducible software environments

module purge
module spider FreeSurfer
module spider FSL
module spider ANTs

# Load an explicit version returned by module spider
module load FreeSurfer/VERSION
module list
recon-all -version

Record module names, versions and commands in each job log. Avoid unversioned module load statements in production workflows.

4. Submit one neuroimaging job

Create scripts/run_subject.sh:

#!/usr/bin/env bash
#SBATCH --job-name=mbciu_fs
#SBATCH --account=punimXXXX
#SBATCH --cpus-per-task=8
#SBATCH --mem=32G
#SBATCH --time=36:00:00
#SBATCH --output=logs/%x_%j.out
#SBATCH --error=logs/%x_%j.err

set -euo pipefail

subject_id=${1:?"subject ID required"}
input_t1=${2:?"input T1 required"}
subjects_dir=${3:?"SUBJECTS_DIR required"}

[[ "$subject_id" =~ ^[A-Za-z0-9._-]+$ ]] || exit 2
[[ -s "$input_t1" ]] || { echo "Missing input: $input_t1"; exit 2; }

module purge
module load FreeSurfer/VERSION
export SUBJECTS_DIR="$subjects_dir"

echo "Started: $(date --iso-8601=seconds)"
echo "Host: $(hostname)"
echo "Input SHA-256: $(sha256sum "$input_t1" | awk '{print $1}')"
module list 2>&1

recon-all -s "$subject_id" -i "$input_t1" -all \
  -parallel -openmp "${SLURM_CPUS_PER_TASK}"

grep -q "finished without error" \
  "$SUBJECTS_DIR/$subject_id/scripts/recon-all.log"
echo "Finished: $(date --iso-8601=seconds)"

Create the log directory before submission, then submit from the project root:

mkdir -p logs
sbatch scripts/run_subject.sh sub-001 inputs/sub-001_T1w.nii.gz derivatives/freesurfer

5. Scale with a manifest and job array

Use a tab-separated manifest rather than inferring identity from directory order:

# manifests/subjects.tsv
sub-001    /absolute/path/sub-001_T1w.nii.gz
sub-002    /absolute/path/sub-002_T1w.nii.gz
sub-003    /absolute/path/sub-003_T1w.nii.gz

Array wrapper:

#!/usr/bin/env bash
#SBATCH --job-name=mbciu_array
#SBATCH --account=punimXXXX
#SBATCH --array=1-3%3
#SBATCH --cpus-per-task=8
#SBATCH --mem=32G
#SBATCH --time=36:00:00
#SBATCH --output=logs/%x_%A_%a.out
#SBATCH --error=logs/%x_%A_%a.err

set -euo pipefail
manifest=${1:?"manifest required"}
line=$(sed -n "${SLURM_ARRAY_TASK_ID}p" "$manifest")
IFS=$'\t' read -r subject_id input_t1 <<< "$line"
[[ -n "$subject_id" && -s "$input_t1" ]] || exit 2

bash scripts/run_subject.sh "$subject_id" "$input_t1" derivatives/freesurfer
Array range must match the manifest. Check with wc -l, inspect the first and last rows, and start with one test subject before launching the cohort.

6. Monitor and right-size resources

TaskCommand
See queued/running jobssqueue -u "$USER"
Inspect completed job accountingsacct -j JOB_ID --format=JobID,State,Elapsed,MaxRSS,AllocCPUS,ExitCode
Cancel a known jobscancel JOB_ID
Inspect output/errorless logs/JOB_NAME_JOB_ID.out

After representative jobs finish, compare requested time, memory and CPUs with actual use. Excessive requests increase queue time and reduce shared capacity; insufficient requests cause timeouts or out-of-memory termination.

7. Use containers safely

module spider Apptainer
module load Apptainer/VERSION

apptainer exec --cleanenv \
  --bind "$PROJECT_ROOT:/work" \
  /path/to/versioned_image.sif \
  command --input /work/inputs --output /work/derivatives
  • Pin the image version or digest.
  • Bind only required directories.
  • Keep secrets out of environment exports and logs.
  • Record the command and image checksum.

8. Built-in sanity checks

  • ☐ Validate the subject ID and input path before computation.
  • ☐ Run one subject end-to-end before submitting an array.
  • ☐ Use set -euo pipefail and quote variable expansions.
  • ☐ Write outputs to a new derivative directory; never overwrite raw data.
  • ☐ Confirm expected completion text and output files.
  • ☐ Review failures individually; do not blindly resubmit the full cohort.
  • ☐ Perform modality-specific visual QC before analysis.
  • ☐ Archive manifests, logs, software versions and checksums.
